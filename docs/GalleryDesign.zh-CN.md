## 初始窗口尺寸建议（2026-10-29）

一般桌面应用的主窗口可优先以 **960 × 660 逻辑像素**作为设计起点。
这是日历实际试用后选定的尺寸，属于**建议规范，不是硬性规定**；
宽高比约为 1.45:1，不要求所有应用统一尺寸或比例。

- 根据各 App 的内容、侧栏、工具栏、信息密度和主要使用场景确定实际初始尺寸；
  小型工具可以更小，多栏编辑器可以更宽。
- 以主要操作可达、文字清晰、布局协调为准，不为套用该尺寸而缩小字体或裁切内容；
  同时考虑当前屏幕的可用工作区。
- 此建议仅针对主窗口初始大小，不规定最小尺寸、不锁定缩放或宽高比，
  不适用于 Dialog／Popover 的尺寸，也不覆盖用户已保存的窗口大小。
  最小窗口尺寸应由各 App 的实际可用布局决定。
- 使用逻辑像素，不按屏幕物理像素硬套；例如 200% 缩放时，
  960 × 660 对应 1920 × 1320 物理像素。

## 浮动 Dialog（2026-10-28）

添加、编辑、确认弹窗统一使用 `LiquidDialog`：背景不透明度 0.95、32px G2 大圆角，下面仍有真实 QML 模糊折射。内部按钮、输入和表单保持实体材质。不得覆写为实体背景，或把整个弹窗 opacity 设置为 0.95。该规定取代旧的普通 Dialog 配方。完整规格见 [Dialogs.zh-CN.md](Dialogs.zh-CN.md)。
> 设置表单统一使用 `SettingsGroup` 和 `SettingsItem`，遵循
> [设置分组与条目规范](Settings.zh-CN.md)：15px 粗体分组标题、12px 普通字重名称、
> 可选的 10px 浅色说明、紧凑条目，以及 `#f7f7f7` 普通无描边分组底板。
> 设置示例中的控件区统一为 24px 高，开关外观为 44×20px 并居中对齐。


### 通用悬浮面板材质（2026-10-28）

Dialog、右键菜单、搜索结果下拉和 Popover 共用 `LiquidPanelSurface`。
`LiquidDialogSurface` 仅提供 Dialog 的 32px G2 外形；统一默认值由
`LiquidStyle.panelMaterialOpacity` 提供，为 **0.95 不透明度**。

1. 采样真实同窗口内容，排除浮层、浮层条目及采样器本身。
2. 用 `LiquidBackdrop.blur` 模糊源纹理，再进行折射。
3. 底色只轻微着色，与不透明度分开；折射玻璃层以 0.95 合成到已模糊底层上，
   不能用 95% 实体底色盖住采样。
4. 只合成一次。不能再次给最终输出乘 0.95，也不能在透明材质下重复叠加
   清晰原图，否则背景文字会重新清晰透出。

文字保持不透明，内部条目和按钮保持普通材质。这里的数值是玻璃层在模糊底层上的不透明度，
不是底色覆盖率，也不是整个 Item 的 opacity。小面板保持紧凑圆角，Dialog 使用 32px G2。
不额外加描边，阴影由 QML 实现。减少透明度或采样不可用时使用不透明回退。
Tooltip 保留自身单独规定的覆盖率，但同样只能合成一次。
这条规定取代上述浮层此前各自叠加 tint / alpha 的配方。

## 规则一　只有悬浮的操作层使用玻璃

适用范围：以下规则用于实际界面的材质组合，不用于删减组件库的液态能力。Gallery 必须保留液态按钮、液态输入框、开关、滑块、选择器等示例，以及普通实色对照。紧凑尺寸与材质选择相互独立。

判断方法：**这个组件是不是浮在内容上方？**

| 判断 | 材质 |
| --- | --- |
| 是 | Liquid Glass |
| 否 | 普通材质 |

Gallery 的“透明”指**窗口内部的层间透明**：右侧原位、整宽矩形的浮动区域覆盖应用自己的滚动内容，
未滚动时，顶部与正文使用相同普通底色，连成完整表面，不显示阴影、高光或分界。
实际内容滚入顶部下方时，材质层才切换为 95% 不透明的液态，透出并模糊下层内容，不添加底部阴影。
回到顶部恢复完整平面。窗口底色始终不透明，不透出其他应用或桌面。
不另画内缩圆角块，不移动窗口装饰器。顶部按钮与下拉框使用轻档液态，左侧导航搜索保留液态输入。

### 悬浮面板材质规则（2026-10-27）

右键菜单、搜索候选下拉、选择器的选项弹层及 Popover 都是覆盖在当前页面上方的
悬浮面板，**面板背景统一使用一层液态材质**。触发方式是搜索、点击按钮还是右键，
都不改变这条规则。

- 面板内部的分组标题、栏目、候选行、菜单项和分隔线使用普通材质；悬停、选中、
  按下均用普通填充。即使用 Button 实现，也按普通条目处理，不给每一行套液态卡片。
- 文字、图标及交互前景保持不透明。需要更实的面板时，提高背景染色／可读性覆盖，
  不修改整个弹层的 opacity；模糊和遮盖应足以避免下层文字与面板文字重叠干扰。
- 采样同一窗口内真实下层内容，排除弹层及采样器自身；使用 QML 模糊与折射，
  不使用 KWin 液态插件或桌面截图。Qt Quick Controls 采样弹层使用 `Popup.Item` 留在同窗。
- 减少透明度、软件渲染或缺少有效采样时使用不透明普通材质回退；保留键盘导航、
  关闭及无障碍行为。
- 保留液态边缘，不因聚焦或打开弹层额外添加蓝色／强调色描边。

这是以后应用接入的默认规则，优先于“浮层里的控件都用液态”之类的泛化说法。
侧栏本体仍遵循下方整块普通面板规则。面板按自身几何使用圆角，液态按钮的胶囊规则
不套用到整个面板。

### 左侧导航材质规则（2026-10-27）

侧栏是一整块连续的普通背景面板，与窗口边缘衔接；不做内缩悬浮卡片，
不使用 LiquidSurface 容器，不叠加容器级液态折射、高光、圆角亮边或悬浮阴影。
背景 `opacity: 0.95` 与 QML 下层模糊是背景合成规则，不代表侧栏本体采用液态材质。
仅背景层使用该不透明度，文字、图标及交互内容保持清晰。

- 导航栏上的搜索框和操作按钮：轻档液态，采样独立侧栏背景。
- 目录分组标题、栏目条：普通材质；选中、悬停和按下使用普通填充。
- 目录条目即使用 Button 实现，也按栏目条规则处理，不启用液态效果。

模糊使用 **QML shader／`MultiEffect` 的 blur**，通过 `LiquidBackdrop.blur` 接入，
起始值与主浮动区域一致为 `.35`。这里的背景模糊不是 `DropShadow` 阴影，
不使用 KWin 液态插件、合成器模糊请求或原生阴影。

宿主应提供同一 QQuickWindow 内、实际位于导航覆盖区域下方的背景／内容子树。
该采样源必须排除导航材质、文字、控件及采样器自身；按真实坐标映射并将输出裁切到导航区域。
不能将右侧页面边缘拉伸或复制成侧栏背景，也不能用示例图片或桌面截图冒充下层内容。
没有下层细节时允许呈现平静材质，不人为添加纹理。窗口底色保持不透明，透出的是本应用内容。

导航背景的 `.95` 不受右侧标题区域 `scrollOffset > 12px` 门槛控制；只有右侧标题区域
保留回顶恢复普通平面的规则。减少透明度、软件渲染或缺少有效同窗采样源时，
回退为 100% 实心导航背景并停止模糊采样，文字和交互状态保持可读。

## 规则三　颜色只有三族

不需要给每个组件单独设计颜色。所有颜色收敛为三族：内容、控件、玻璃。
浅色主题的普通实色控件用纯黑字，液态控件用不透明、稍浅的深灰字；主操作、危险与禁用文字保留各自的语义色。

| 族 | 用途 | 浅色主题 | 深色主题 |
| --- | --- | --- | --- |
| 内容 | 正文、列表、编辑器、内容面板 | `#FFFFFF` | `#1C1C1E` |
| 内容（次级） | 分组底、条纹区、次级面板 | `#F5F5F7` | `#242426` |
| 控件 | 普通按钮、搜索框、设置项 | `#EDEDF0` | `#3A3A3C` |
| 控件（Dialog） | Dialog 容器底色 | `#F7F7F9` | `#2C2C2E` |
| 玻璃 | 由背景决定（见下方 IF/ELSE） | 浅色自适应玻璃 | 深色自适应玻璃 |

### 3.1 Dialog 与按钮不共用同一底色

Dialog 和普通按钮同属控件族，但**不强制使用相同背景**。Dialog 是容器，按钮是容器内的控件，两者必须保留一级亮度差，否则按钮会陷进 Dialog 里：

| 主题 | 更亮的一方 | 取值 |
| --- | --- | --- |
| 浅色 | Dialog（容器） | `#F7F7F9` 亮于 `#EDEDF0` |
| 深色 | 按钮（控件） | `#3A3A3C` 亮于 `#2C2C2E` |

亮度差的方向随主题翻转，差值保持在“可辨”一级即可，不要拉到两级以上。

### 3.2 给 AI 的 IF / ELSE

```text
IF material == Glass
    background = AdaptiveGlass
    // 禁止用固定 RGB 代替玻璃

ELSE IF theme == Light
    content.background = #FFFFFF
    content.secondary  = #F5F5F7
    control.background = #EDEDF0
    dialog.background  = #F7F7F9
    search.background  = #EDEDF0

ELSE IF theme == Dark
    content.background = #1C1C1E
    content.secondary  = #242426
    control.background = #3A3A3C
    dialog.background  = #2C2C2E
    search.background  = #3A3A3C

ELSE
    background = SemanticColor
```

## 实现位置

controlBackground、dialogBackground。Gallery 启用 compactDesign；共享控件通过

普通材质由宿主在具体位置显式选择，其他应用默认行为保持兼容。页面布局值在
`demo/gallery/components/MaterialSpecTokens.qml`。

右侧内容场景包含不透明底色与完整滚动页面，填满右侧区域。整宽矩形浮动层位于其上方，
紧贴原有上／左／右边界，radius=0，不画内缩圆角卡片。装饰器、标题和工具栏在原坐标排布，
装饰器仍位于右侧 y=0 的 30px 行，窗口控件右距 14.5px、顶距 10.5px 保持不变。
页面首屏为该区域预留 30 + 16 + 48 + 12px，滚动时页面真正经过浮动层下方。
OverviewPage 与 ComponentPage 暴露实际 scrollOffset（contentY - originY，下限为 0）。
偏移超过首屏间隔 12px、真实内容进入覆盖区域后才启用浮动材质与模糊；回顶自动关闭。
只切换材质，不移动装饰器、工具栏或页面尺寸；切换组件页时滚动归位。
语言／主题按钮和背景选择器使用轻档液态，共用只捕获主区材质背景的采样器，
不采入按钮自身、文字或窗口装饰器。控件文字仍为 11px，不随材质层变透明。左侧导航背景遵循上方 `.95` 整块普通面板规则；导航项
使用普通填充，导航条目间距为 0，行高为 30px，字号为 12px，字重统一为 Font.Medium（500）；选中蓝色背景上下各内缩 2px，选中文字为白色，悬停填充仍覆盖整个实色条目，浅色主题下悬停为 `#dbdbdd`、选中为蓝色强调色。导航栏搜索框与操作按钮显式启用轻档液态，采样独立侧栏材质背景，减少透明度时回退普通控件。目录卡片、代码和列表使用内容色族；浮动 Dialog
使用 0.95 不透明度的 G2 液态背景，Dialog 底色仅作为着色与回退；按钮使用实体控件底色。浮动搜索样板只有外层玻璃，内部搜索和列表为普通材质。
Button、Input、Select 规则页采用接近 macOS 15 的紧凑文字层级：一级标题 24px／Bold／主文字色，规则标题 17px／DemiBold／主文字色，位置小标题 15px／DemiBold／主文字色，说明文字 13px／Normal／次要文字色。侧栏分组标题为 11px／DemiBold／次要文字色，上下留白分别为 12px 和 4px。这些是 Gallery 的取值，不作为 Apple 控件的固定尺寸。

## 自适应玻璃

adaptiveGlass 通过现有 LiquidBackdrop 采样同窗口内的独立兄弟背景，使用
LiquidSurface 已有 shader 按像素亮度做可读性处理。颜色由真实采样与主题共同
决定，禁止用一块固定 RGB 填充冒充玻璃。中性薄 tint 只作主题调节，不是玻璃底色。

合成顺序：应用不透明底色与实际滚动内容 → 同窗口 QML 模糊采样 → 95% 液态浮动材质 → 清晰控件。
右侧标题区域未覆盖内容时停止其模糊采样，使用与正文相同的实心底色。覆盖内容时，
LiquidBackdrop.sourceItem 指向包含真实列表、卡片和文字的 contentScene，排除浮动层本身；
使用 QML MultiEffect 模糊（.35），原始内容继续正常绘制。LiquidSurface 开启 layer.enabled，
仅对浮动材质合成结果设置 opacity=.95，文字、按钮和装饰器保持不透明。
Window.color 与内容底色均不透明，所以剩余 5% 透出的是本应用内容，不是窗口外的像素。
浮动区域不添加底部阴影。不请求 KWin 液态插件、
compositor blur 或原生阴影。背景选择器只控制组件示例背景，不参与主界面浮动层采样。
减少透明度时使用 100% 实心材质与普通顶部控件。

一般轻玻璃边缘折射 .6、放大 1、反射 .12。右侧浮动材质和导航搜索采用共享
light 档光学强度：静止折射 1.5、放大 1.012、反射 .28；不增加厚亮边或多层阴影。
普通控件与卡片无投影，浮动容器最多一层轻阴影。光学原理页作为明确标注的
悬浮操作层演示，不作为普通内容表面模板。

## 焦点与选中规则（2026-10-27）

**给 AI 和应用接入者的明确提示词：液态搜索框、输入框、按钮和选择器在获得焦点、
被选中、按下或展开时，保留组件自身的玻璃边缘，不得额外添加蓝色／强调色边框、
外部焦点环，也不得在应用包装层叠加 Rectangle 描边。不要把普通实色控件的焦点规则
套到液态材质上。禁止自行硬编码 `#9CCAFF`、`#007AFF`、`#0A84FF` 等焦点颜色。**

| 实际材质 | 焦点与选中表现 |
| --- | --- |
| 液态搜索、输入、操作按钮、选择器 | 保留共享组件的玻璃边缘及内建状态表现；不额外加焦点／选中描边 |
| 普通实色控件，包括明确回退为实色的控件 | 使用组件的 `AppTheme.focusRing` 语义焦点样式，不在应用中自定固定颜色 |
| 普通目录栏目条 | 保留规定的普通选中／悬停填充；不改成液态，也不增加液态轮廓 |

以实际渲染材质判断，不能仅看组件名是否以 `Liquid` 开头。`activeFocus`、
`visualFocus`、`checked` 与弹层展开是不同状态，不能据此推导“液态必须有蓝框”。
必须保留焦点归属、输入光标、文字选择、Tab／方向键／Enter／Space 操作及无障碍语义。
通过共享组件已有状态属性表达交互，不在外面再画一层边框。

参考实现：`shared/qml/controls/LiquidTextField.qml` 的焦点描边只在
`!root._liquid && root.activeFocus && root.enabled` 时显示；`LiquidSelect.qml`
也仅在实色形态绘制焦点边框。这是材质规则，不是关闭焦点的理由。
本条优先于旧文档中未区分材质的“2px 焦点环”通用表述及历史接入记录。
部分旧控件仍可能需要按此规则对齐；本次文档更新不代表已完成全库实现审计。
