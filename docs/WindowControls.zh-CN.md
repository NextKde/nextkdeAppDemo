# 窗口按钮的绘制权与布局

[English](WindowControls.md)

应用决定有哪些按钮、各自放在哪里；可选的平台适配器可以把绘制和窗口操作交给合成器。可移植组件必须在没有 NextKde、KWin、Wayland 和适配器时仍能使用。

## 共享控件

标准排列和应用自绘回退统一使用 `KosWindowControls`：

```qml
KosWindowControls {
    targetWindow: root
    maximizeMode: true
    actions: ["close"]
    circleSize: 14
    buttonWidth: 22
    buttonHeight: 22
}
```

- `actions` 是实际按钮列表，支持 `maximize`、`minimize`、`close`，每种最多一次。默认按此顺序显示三个；`[]` 表示没有按钮。
- `maximizeMode: true` 表示绿色按钮执行最大化/还原。为兼容旧应用，`false` 保持原来的全屏行为，不交给仅支持最大化的 NextKde 协议。
- `buttonLayout` 提供圆点的 `{action, x, y, width, height}`，坐标相对于该控件。必须读取实际布局，不能按固定右上角偏移或假定的数量猜位置。
- `externalDrawing` 默认 `false`。只有应用适配器确认合成器接管后才能设为 `true`；控件隐藏并禁用自绘按钮，但保留布局占位。服务消失时立即恢复为 `false`。
- `hoverGlyphs` 默认 `true`；适配器可以传入统一的始终显示/悬停显示偏好。自绘回退必须保留键盘操作和可访问名称。

按钮增减、顺序、位置、尺寸或可见性变化时，替换完整声明。删除的按钮必须同时停止绘制和接收点击。不能按序号、颜色采样或窗口标题判断动作；只有关闭按钮的窗口不能出现多余的最大化、最小化按钮或残留点击区域。

## 可选的 NextKde 平台适配

平台代码放在使用组件的应用或其平台接入包，不放进本仓库的 `shared/qml`。不能给可移植控件添加无条件 KWin/Wayland 导入或轮询定时器。本库只提供布局数据和自绘控制，不包含原生协议实现。

NextKde 适配器使用 `Kos.SurfaceShape.WindowControlSlot` 和 `kos_window_controls_v1` 的版本 2，把每个矩形转换到对应窗口 `wl_surface` 的逻辑坐标。非标准布局也可以使用：将不同标题栏分组的按钮合并为**每个 surface 一份列表**，不要注册多个互相竞争的适配器。顺序、间距和各按钮大小不必遵循标准 Row。

接管必须同时满足：协议可用、已有的 **KOS 窗口外观** 开关开启、窗口及布局可接管、合成器确认。不要另加一个默认接入开关，也不要通过桌面名称或 app ID 猜测能力。旧版协议、其他桌面、关闭接入或拒绝的布局都保留自绘。连接存在时，共用的按钮图标偏好同样用于自绘回退。无需选择 KOS 窗口装饰器。

布局和状态变化触发事件，在布局完成后发送变化的列表；不定时轮询。合成器发送 configure，应用切换自绘状态、确认序号并提交下一帧；几何和绘制权随 surface commit 生效。服务消失立即自绘。不支持的变换或半透明按钮请求交还绘制权。

KWin 只画声明的圆点：背景透明，不采样标题栏、不画背景色块。空列表不绘制、不拦截；按钮间隙归应用处理。声明过的 surface 即使回退也跳过旧位置浮层；未适配第三方窗口仍走已有平台路径。

当前 NextKde v2 支持零到三个唯一动作，圆点为 6–40 逻辑像素正方形，不允许重叠或越过窗口边界，整体包围区域不超过 4096×4096。未知/重复动作和无效几何拒绝整份列表，不能静默截断或猜布局。已最大化时，最大化动作执行还原。增加其他动作需要显式演进协议。

## 验收

仅在虚拟机或托管 CI 验证：三个/一个/零个按钮、重排和尺寸变化、窗口间独立性、移除后的点击区域、实际窗口动作、开关变化、服务不可用回退，以及可选模块缺失时仍能启动应用。纯组件测试通过不等于合成器或 GPU 验收。NextKde 原生实现及虚拟机测试入口在其仓库的 `docs/CooperativeWindowControls.zh-CN.md` 和 `tests/cooperative-controls`。
